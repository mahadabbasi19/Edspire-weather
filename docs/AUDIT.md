## Important failures found and resolved

- An initial OpenWeather key returned 401. Real fallback worked; the user supplied a corrected key, and both primary endpoints then returned 200. No error was hidden or incorrectly blamed on a platform limitation.
- Public anonymous Vercel preview verification returned 403 despite the CLI reporting Ready. That URL was not treated as working. The user had no Vercel project/login, so the app was deployed on allowed GitHub Pages instead.
- Actual network blocking left `navigator.onLine=true` in the standalone browser check. The cached shell/data loaded, but relying on the browser hint alone hid the offline banner. Network failures are now classified separately and show a connection-unavailable banner with saved data and retry; a regression test covers this. [MDN documents the unreliable online hint](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/onLine).
- Axe found muted-text and night-control contrast defects; colors/opacity were corrected, then all four theme/day combinations passed.
- Chromium's browser permission query/request could report granted while the host's notification permission and actual worker notification display were denied. Production checks the effective permission, errors remain visible, and no native success is claimed.
